# 语言与主题

两个下拉都在顶栏右端。切换都不需要重启，而且都会被记住。

## 语言

`src/i18n.ts` 里是中文、英文两张各 78 键的等长表；导出的 `missingKeys()` 会报告只出现在其中一张
表里的键，界面回归检查会断言它返回空。没有历史选择时按 `navigator.language` 判定，所以中文
Windows 首启就是中文界面。选择存在 `seqpanel.lang`。

切换语言会重建所有带译文的内容：命令表、预设、参数表单、步骤列表、结果区和状态栏。

### 故意不翻译的部分

| 文本 | 来源 | 为什么保持英文 |
|---|---|---|
| 命令名（`clean sites`、`compute distance`） | CLI 本身 | 它们是参数，不是文案 |
| 开关名与类型（`--char`、`stringSlice`） | CLI 本身 | 同上 |
| 开关说明、默认值、整段 `--help` 文案 | CLI 本身 | 翻译就等于在面板与上游之间塞进 GoAlign 自己没用过的词 |
| 统计表、距离矩阵、比对本体 | CLI 的 stdout | 那是数据 |
| GoAlign 的 `[Error] ... message:` 文本 | CLI 的 stderr | 面板原样抽取，不改写 |

SeqPanel 自己写的文案都是双语的，工具包用 `nameZh`、`descriptionZh`、`labelZh`、`helpZh` 四个字段
携带中文：5 个预设的名字与说明、5 个位置参数命令的标签与提示都属于这一类。

后端错误也遵守同一套分工。Rust 里从不写面向用户的句子，只返回 `E#<key>|<detail>`，由前端按当前
语言渲染 `E.<key>`。因此新增一条错误提示是在两张表里各加一行，而不是改 Rust。

## 主题

三档——*跟随系统*、*浅色*、*深色*——存在 `seqpanel.theme`。

*跟随系统*监听 `prefers-color-scheme` 变化并即时响应。三档都会通过 Tauri 的窗口 API 同步原生
Windows 标题栏颜色，所以边框和客户区不会互相矛盾。

配色来自 `:root` 上的 CSS 自定义属性（`--bg`、`--panel`、`--ink`、`--muted`、`--line`、`--accent`、
`--accent-text`、`--figure-bg` 及其深色覆盖）。两套色板都要求正文、次要文字，以及蓝底与其白色文字
之间至少 4.5:1 的对比度。

有一个取舍在启动瞬间可见。内容安全策略是 `default-src 'self'` 且不含 `'unsafe-inline'`，这就排除了
那段能在首帧之前套用已存主题的内联预绘脚本。所以如果你显式选了与系统相反的主题，可能会看到一帧
系统主题闪烁，样式表与模块加载完成后才纠正。选*跟随系统*可以完全避开。

GoAlign 画的 PNG 热图默认按浅色页面理解，因此图片底色在两套主题下都保持白色，变的只是它周围的
边框与文字。

## 重置

两个选择都在该应用自身 origin 的 `localStorage` 里。删掉 `%APPDATA%` 下的 `app.seq.panel` 目录，
语言、主题、记住的可执行文件路径和输入路径都会回到初始值，并强制重新反射内置工具。
